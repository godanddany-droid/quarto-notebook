Week 04 - Exploratory Data Analysis (EDA)

Monday

Exploratory Data Analysis (EDA)

EDA Mindset

Is iterative, investigative and visual.

Expect: -Go back and forth between steps -Revise assumptions -Discover data issues late in the process -Ask better questions as you learn more

Understanding the context

Before touching the data understand: -Where did the data come from -Why was it collected - Who or what does each row represent? -What decisions will this data support?

Key questions -Is this observational or experimental data? -Are there known biases? -Is time involved -Are there units, definitions, or domain rules?

Poor context understanding leads to correct analysis of the wrong problem.

Data Validation (Trust but verify)

Validation answers one core question:

Is this data structurally and logically valid?

This step focuses on correctness, not insight.

Structural Validation

-Do all columns exist? -Are data types correct -Are there unexpected nulls? -Are identifieres unique when they should be?

Logical Validation

-Are values within expected ranges? -Do dates make sense chronologically? -Do relationships between variables violate domain rules?

RED FLAGS:

Negative ages Future timestamps Duplicate IDs Impossible combination of values

Data Cleaning(Fixing What’s Broken)

Cleaning addresses errors, inconsistencies, and noise.

Typical tasks:

-Handling missing values -Fixing inconsistent labels or categories -Correcting obvious data entry errors -Removing or flagging duplicates

Important principle:

Cleaning should be conservative and documented.

Avoid “fixing” data unless:

-You know the cause -The correction is defensible -you preserve original values when possible

Data Massaging (Making Data Usable)

Massaging prepares data for analysis and exploration, not modeling.

This step is about shape and representation.

Common activities:

-Renaming variables for clarity -Creating derived variables -Converting units or scales -Reshaping data (wide - Long) -Standardizing formats (dates, categories, text)

Key idea: Clean data can still be unusable massaging makes it analysis-ready.

Univariate Exploration (One Variable at a Time)

Now you start learning what the data looks like.

For each variable, ask:

-What values occur? -What is typical? -What is extreme? -What is missing?

Conceptually

Numeric variables distribution, spread, skewness

Categorical variables frequency, dominance, rarity

This step builds baseline intuition.

Bivariate Exploration (Relationships)

Next, explore how variables relate to each other.

Ask questions like:

-Does one variable change with another? -Are there strong associations? -Are relationships linear, nonlinear, or absent?

Focus on:

Direction Strength Consistency Exceptions

Many insights live in relationships, not individual variables.

Multivariate Exploration (Context Matters)

Multivariate analysis looks at relationships conditiones on other variables.

This helps answer:

Does this relationship hold across groups? Is this pattern driven by a subset? Are there interaction effects?

This step often reveals:

Hidden structure Cofounding Variables Simpson’s paradox-type effects

Outliers and Anomalies (Signal or Noise?)

Outliers are not automatically bad.

Ask: Are they errors? Are they rare but valid cases? Do they represent a different process?

Important distinction: Outlier extreme but valid Anomaly inconsistent with data-generating process

Never remove outliers without understanding them.

Assumptions checking

Before modeling, EDA helps you check:

Distributional assumptions Independence Stationarity (for time-based data) Linearity or monotonicity

This step informs:

Feature engineering Model Choice Transformation needs

EDA is Iterative

EDA does not end cleanly.

You will:

Discover issues late Revisit Cleaning Create new variables mid-analysis change direction based on findings

This is normal and expected.

Key Takeaways

EDA is about understanding, not proving

Most errors are found before modeling

3.2 Decide on a missing data strategy

aq_clean <- aq_raw %>%
group_by(Month) %>%
mutate(
Ozone   = ifelse(is.na(Ozone),   median(Ozone, na.rm = TRUE),   Ozone),
Solar.R = ifelse(is.na(Solar.R), median(Solar.R, na.rm = TRUE), Solar.R)
) %>%
ungroup()

colSums(is.na(aq_clean))

      0       0       0       0       0       0
